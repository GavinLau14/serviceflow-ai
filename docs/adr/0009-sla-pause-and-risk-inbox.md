# ADR 0009：SLA等待补偿与风险读模型

状态：已实现（v0.9.0）。

等待客户属于业务暂停，不能只停止扫描、恢复时却消耗掉客户等待时间。进入WAITING_CUSTOMER记录resolution_paused_at；离开时在工单版本更新成功之后锁SLA，计算非负微秒差，顺延resolution_due并累计paused_micros，然后清空起点。状态、截止补偿、事件、审计和outbox共享事务，扫描也先锁工单后锁SLA。重复/并发的客户操作只有一个状态转换成功，避免双重补偿。首次响应时限不暂停，已存在的超时余额不被抹除，已触发升级不回滚。

V10既有等待从迁移UTC时刻开始计时，不根据不完整历史补造时长。暂停中的解决截止仍展示已结算值，恢复时结算当前周期；详情提供asOf与累计秒数，明确向下取整。时钟倒退补偿为0；当前未针对长时间异常系统时钟实现纠偏。

风险队列采用独立只读模型，工作人员范围与原工单相同，客户不可读内部SLA。只扫描当前未关闭工单，取尚未响应/未暂停解决的最早截止，截止<=asOf为超时，(asOf,asOf+30m]为临期。统计、分页与列表同一REPEATABLE_READ快照及UTC时刻；汇总不受搜索条件影响，且不替代最终详情权限检查。

所有截止表达式保持MySQL原生DATETIME类型，避免CASE中的字符串哨兵使LEAST返回字符串、令微秒格式差异破坏“截止瞬间”边界。真实MySQL边界测试复现旧表达式比较为0、日期类型比较为1，当前使用只含日期列/NULL的CASE。

前端队列只提供查看入口，分派和处理仍走原确认与版本校验。手机使用常驻工具栏入口，独立组件响应式测试与实际App导航测试共同覆盖。当前无SLA多级策略、自定义工作日历、实时推送或生产规模查询性能承诺。
