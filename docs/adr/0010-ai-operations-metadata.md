# ADR 0010：AI运行元数据与健康核验的边界

状态：已实现（v0.10.0）。

管理员需要区分检索降级、调用异常和建单关联，但全局运行台不应成为读取所有客户咨询的入口。因此新接口只投影运行UUID、固定模式、记录耗时、引用条数、原始提案标记、工单关联、人工接管标记和时间；不查询返回客户身份、咨询、回答、引用正文、提案正文或hash。所有全局记录、汇总与健康接口只向ADMIN开放，工单跳转仍走原详情授权。

统计、筛选计数和分页在一个REPEATABLE_READ快照及同一UTC asOf中完成，窗口为[asOf-hours,asOf]，最多168小时。汇总不受模式和工单筛选影响。先用JSON_VALID将损坏JSON替换为空对象，再投影元数据；模式以二进制严格匹配并输出固定常量，其余统一unknown。真实MySQL证明普通比较会把尾空格模式等同于规范值，回归验证已覆盖。负耗时不参与均值，缺失或异常的引用数组条数为null。

这是历史日志读模型，不代表当前引用授权或提案可执行性；已撤回来源的旧日志仍保留，原始咨询/回答也仍在业务数据库中保存。运行台不修改这些历史事实。记录耗时沿用AiService在写日志前采集的处理时间，不是单独的模型延迟或浏览器端到端耗时，均值不能当生产性能基准。

健康接口使用独立短探测：异步HTTP请求整体等待最多3秒，订阅者累计超过4096字节时取消订阅，回执字段严格校验，异常只返回固定UNAVAILABLE和未知布尔值。缺少后端AI接入配置则不发起网络请求。网络探测不占用数据库事务。REACHABLE仅证明Python健康接口可达，不证明服务鉴权、真实模型调用或回答质量；有模型配置也不等于完成验收。

前端分别管理历史和健康请求，切换账号/角色或卸载后丢弃旧回包，失败清空相应旧结果；不把健康失败误当历史记录丢失。当前无自动告警、分布式追踪、异常归因、日志清理或大规模查询性能承诺；后续再考虑预聚合、保留策略和实际模型评测，不引入额外观测框架。
