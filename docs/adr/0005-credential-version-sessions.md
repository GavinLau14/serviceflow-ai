# ADR 0005：通过凭据版本使旧会话失效

状态：已实现。范围：用户自助修改本人密码。

## 决策

MySQL users保存credential_version，Redis每个会话保存账号ID及签发时的版本。会话解析原本已经查询当前活跃用户，因此同时比较版本不会增加一次数据库请求。改密在账号行锁内验证旧密码，单条UPDATE同时写新BCrypt哈希和递增版本。

## 原因

按账号收集token列表并逐个删除会引入双写、遗漏和并发登录窗口；全库SCAN不适合作为必需的改密步骤。MySQL版本比较把密码和会话失效条件放在一个事务中，外层回滚不会提前撤销Redis会话。使用旧用户快照在提交后签发的会话仍绑定旧版本，会被拒绝。

## 兼容和边界

旧Redis值只有用户ID，视为版本0，迁移后现有账号默认0；首次改密后，旧格式不能重新获得有效性。版本字段和哈希都不对外序列化。旧会话键保留原TTL，失效不等于立刻物理清理。已有请求只在入口鉴权，不强制中断已执行中的请求。需同步更新API实例，不能将忽略版本的旧API纳入混合部署。

这不是密码找回、管理员重置、密码历史或多因素认证。当前演示不具备这些能力。自助改密需旧密码、二次输入和显式确认；本次开发没有修改本地现有演示账号的密码。
