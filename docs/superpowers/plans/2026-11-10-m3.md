# M3 design / execution plan

Proceed under user's engineering autonomy. Backend remains independent Java writer; no remote push. Preserve M2 live-LLM limitation.

1. Operations: least-active-load same-team automatic assignment under team row lock; configurable enabled and capacity; no candidate stays OPEN. SLA first response and resolution deadlines, scheduled bounded scans, once-per-ticket upgrade via CAS, pause resolution escalation during WAITING_CUSTOMER. Transactional audit/outbox on workflow changes, idempotent delivery to per-user notifications. Server-scoped notification/audit/SLA REST views. Real MySQL concurrency/rollback tests.
2. Collaboration: explicit customer-confirmed human handoff creates an assigned business ticket from original message, idempotent per AI run; existing assigned agent starts processing as takeover with durable trace. Closed ticket to DRAFT knowledge by assigned agent/same-team supervisor/admin, explicit supervisor/admin review before PUBLISHED. Knowledge must exclude customer description/PII by default, manual editable resolution-only draft, not automatically added to AI corpus. Scoped tests.
3. Frontend: evaluate current UI and user's feedback. Improve actual workbench composition and navigation, add notices/SLA/audit/handoff/knowledge actions in relevant roles. Keep existing tests and responsive keyboard access. No mock data passed as backend facts.
4. Full regression, live cross-role demonstration, independent review, result docs and single local M3 commit. M4 full deployment remains separate.

Shared contracts:
GET /api/notifications → array {id,ticketId,title,body,read,createdAt}; POST /api/notifications/{id}/read {}.
GET /api/tickets/{id}/sla → {firstResponseDue,resolutionDue,firstRespondedAt,escalatedAt,...}; GET /api/tickets/{id}/audit → array of audit records, staff only scoped.
POST /api/operations/scan {confirmed:true} staff supervisor/admin scoped; result counts. Config tests app.workflows.auto-assign=false to preserve M1 tests, normal app true.
POST /api/ai/runs/{id}/handoff {confirmed:true,category:DEVICE|APPLIANCE} (explicit customer queue selection) customer owner; uses persisted original text (new ai_runs message field for future runs; backfill from safe proposal only, old missing rejects with actionable error), same ticketId reuse as execute. Handoff safe even retrieval_only/error because customer explicitly requests human; no false AI-success claim.
GET /api/knowledge → role-scoped list (staff only); POST /api/tickets/{id}/knowledge {title,content,confirmed:true} closed only; POST /api/knowledge/{id}/review {approved:boolean,confirmed:true}; publishing never writes Qdrant automatically.

Migrations: operations V3, collaboration V4. Agents own assigned files and don't commit independently. Root handles frontend and integration.

Ruling: 人工接管分类由客户显式选择，避免无LLM时默认数码设备导致家电被错误自动分派。
