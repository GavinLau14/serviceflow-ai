# 通知收件箱补齐

现状：公开通知查询只返回最近100条，界面没有未读筛选或历史分页。此轮延续现有客服工作台，不引入外部推送或新框架。

设计：新增兼容性端点 GET /api/notifications/inbox，提供 items、total、unreadTotal、page、size；所有 SQL 固定绑定登录用户，未读总数不受筛选或页码影响。单个只读事务保证每次响应的计数和列表一致。新增 POST /api/notifications/read-all，要求 confirmed=true，只更新本人未读记录并返回本次更新数。保留原 GET /notifications，避免破坏已有演示脚本。

界面：消息页增加全部/未读切换、总未读数、20条分页和明确确认后的全部已读。单条已读后重新读取服务端结果；未读筛选的末页清空后自动回退，过期请求不能覆盖新视图。沿用 DESIGN.md 的叶色/橘色、系统字体、Element Plus 标准控件。

实现与验收：
1. Java 集成测试先验证新端点缺失，再实现服务/控制器及 V5 未读索引。
2. 浏览器测试先覆盖分页、筛选、末页回退、批量确认和错误恢复，再实现前端。
3. 完整后端 verify、前端类型/构建、Playwright；实际本地容器更新与通知 API 验证。
4. 记录本轮实际验证和局限，独立本地提交，不推送。
