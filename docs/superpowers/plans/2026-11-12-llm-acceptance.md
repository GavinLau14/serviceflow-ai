# 真实模型验收补齐

目标：将 M2 剩余的真实模型验收变成可重复执行的流程，保留未配置时的明确未验收状态。

采用现有 Java 公开 API 执行六条固定问题；不直接访问 Python、不读取模型 Key、不自动执行工单提案。相较仅测试模型 HTTP 接口，这能覆盖检索、模型、Java 响应边界和 AI 调用记录。相较全量生成工单，本轮只验证草稿及未授权不写入业务数据，避免污染业务状态。已有 smoke-stack.py 继续承担实际建单闭环。

实现顺序：
1. 新建脚本验收器的回归测试，先验证缺模块失败，再实现。
2. 固定六条用例与演示知识指纹：两类报修、知识问答、未知问题、费用承诺、越权诱导。
3. 实现登录、逐条 assist、引用/意图/草稿字段检查、历史与工单数量检查、退出码与脱敏报告；不调用 execute/handoff。
4. CI 加入离线验收器测试。增加本地配置和运行说明。
5. 执行离线回归、现有 AI 合同测试、本地无 Key 检查，记录实际结果并单独提交。不将离线夹具或 retrieval_only 记录为远端模型通过。

退出码：0 全部通过；1 验收失败；2 未执行或配置未就绪。报告仅包含用例 ID、模式、检查结果和调用 ID，不保存 Key、登录 token 或原始上游错误。

实施时发现：Java 将有引用的合法转人工结果改成 error 并丢弃引用。新增集成测试先观察到 mode=error 的失败，再修正为固定转人工说明、保留引用、confidence=0、移除全部提案。没有来源的 rag 仍失败关闭。完整回归结果另见 LLM_READINESS_RESULTS.md。
