# v0.7 受控知识发布与撤回

## 权限与数据

只有管理员可以把审核通过的条目发布给全部已登录客户。管理员需另填公开标题/摘要（160/1500字符），确认已脱敏与全客户公开；不自动复制内部正文或审核意见。每次变更创建不可变发布UUID/递增版本，替代旧版本时撤回旧UUID。员工按原工单范围查看发布历史；客户只能读取当前已同步的公开快照，不能获取原工单/知识ID或人员信息。

## 检索边界

Java将当前ACTIVE且SYNCED的公开快照白名单随每次assist发送Python，最多50条。Python在独立Qdrant集合写真实向量，检索按白名单过滤，并逐字段验证payload与Java快照一致。固定演示集合保持独立。无模型Key仍是真实检索原文、retrieval_only。

发布授权先在MySQL事务提交，外部索引随后执行；失败明确记录FAILED、不可引用、支持重试。撤回先提交WITHDRAWN，再尝试删除向量；残留/晚到向量不具备授权。旧upsert返回时若已撤回，再做清理。物理删除只提供最佳努力确认，不承诺抹除已展示/发送至模型的数据。

## 并发和旧结果

Java在最终返回并记录AI结果的事务中锁定引用快照重新校验，过期引用整条回答失败关闭。旧历史读取时隐藏已撤回引用的建议；旧提案执行时再次锁定和校验，阻止撤回后建单。已创建工单不删除，人工接管仍可根据用户原问题继续。已送达/已通过校验的在途结果无法强制收回，撤回成功后开始的新请求不得引用旧内容。

## 实现顺序

1. 添加失败的Java发布/授权/撤回集成测试；实现V8、发布快照/全局发布计数锁、Java服务和控制器。
2. 添加Python协议与payload篡改测试，再实现内部upsert/delete及每请求白名单检索；独立真实Embedding/Qdrant测试。
3. 接入AI网关白名单、最终校验、历史遮蔽和执行拦截，补并发边界测试。
4. 管理员发布面板与来源预览，显式双确认、状态/重试、撤回；员工只读，客户来源只返回公开快照。
5. clean verify、pytest、浏览器、源码Compose与真实发布→检索→撤回验证，经PR/main CI后发布v0.7.0。真实远端LLM质量验收仍保留未完成。
