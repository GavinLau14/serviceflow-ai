# M1 Implementation Plan

> 执行方式：主代理按用户授权在当前会话直接实施；每阶段以真实验证结果更新账本。

**Goal:** 交付安全隔离、可运行的售后工单闭环。
**Architecture:** Java 模块化单体负责业务写入，Redis 管理会话；前端同源代理。AI 在 M1 明确未启用。
**Tech Stack:** Java 21 / Boot 3.5.16 / MyBatis 3.0.5 / MySQL 8.4 / Redis 7.4 / Vue 3 / TS / Element Plus。
**Spec:** docs/superpowers/specs/2026-11-10-serviceflow-design.md

## Global Constraints

独立仓库、数据库、容器和端口，不操作 ProcureGuard。无远程推送和生产部署。无真实密钥入库。M1 不提前实现 AI。

## Review Focus

跨用户/团队 IDOR；客户查看内部备注；并发流转/过期版本；缺失授权确认；异常状态跳转和无效筛选。

### Task 1: 身份与权限集成契约

Files: backend/pom.xml, backend/src/test/java/com/serviceflow/WorkflowIntegrationTest.java, backend/src/main/resources/db/migration/V1__core.sql, compose.yaml。
Interfaces: POST /api/auth/login → token/user；GET /api/auth/me；POST /api/auth/logout。后续业务消费服务端 User 身份，绝不信任请求角色。
- [ ] 写 MockMvc 集成测试覆盖无凭据、错误密码、登录与登出；启动独立 MySQL/Redis，运行并确认缺失接口导致失败。
- [ ] 实现 Flyway 用户/团队表、Redis 会话、SecurityFilterChain、统一错误；运行同一测试直至通过。

### Task 2: 工单业务闭环

Files: backend/src/main/java/com/serviceflow/ticket/*, backend/src/main/resources/mappers/TicketMapper.xml, 同一集成测试类。
Interfaces: /api/tickets GET/POST；/{id} GET；/{id}/assign、transition、comments POST；所有变更传 version，敏感操作传 confirmed。
- [ ] 先写客户创建/隔离、团队隔离、分派、处理、拒绝方案、确认关闭、内部备注和过期版本测试；观察失败。
- [ ] 实现 DTO → Controller → Service 事务 → MyBatis，分页总数与条目用同一 scope；运行完整测试并确认 MySQL 迁移及约束。

### Task 3: Vue 工作台与演示

Files: frontend/src/{App.vue,api.ts,style.css}, frontend/e2e/workflow.spec.ts, frontend/package.json。
Interfaces: 类型定义与后端 DTO 一致；凭据只在 sessionStorage，会话失败回登录。
- [ ] 写浏览器闭环：客户创建、主管分派、客服解决、客户确认；运行观察缺失 UI 失败。
- [ ] 实现响应式工作台、详情、时间线、空/错/加载状态；vue-tsc 与 Vite build；桌面/窄屏检查。
