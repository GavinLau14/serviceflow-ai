# ServiceFlow AI 设计

用户已授权主推进工程师直接执行并选择合理版本，故不再增加设计批准环节。以下为工程决策，不代表用户逐项指定。

目标：面向 Java 后端 + AI 应用实习求职，交付可复现、可测试的售后业务闭环。M1 首先完成真实数据和权限流转，M2 再接模型。

备选：直接改造 JPA 工单项目（会携带无关功能和迁移负担）；微服务拆分工单/用户/通知（增加分布式事务）；选择按 auth/ticket/common 分域的 Spring Boot 模块化单体，Python 独立推理。选择第三种，保留跨进程权限边界，不增加注册中心或消息中间件。

## M1 范围

- 登录、当前身份、登出，Redis 存储可吊销的短期 opaque bearer session，BCrypt 密码，登录限流。
- 客户创建、分页/状态/关键词过滤、详情、公开回复；客服只看分配给自己的工单；主管只看本团队；管理员全局。详情、回复、操作、列表统计均按相同数据范围。
- 工单状态 OPEN → ASSIGNED → IN_PROGRESS → WAITING_CUSTOMER → CLOSED；客户可拒绝方案回 IN_PROGRESS；关闭必须客户本人显式确认。主管/管理员分派，执行前显式确认。客服内部备注对客户不可见。
- MyBatis 参数化 SQL，Flyway 建表，外键/索引，乐观版本控制；业务变更、评论、事件同事务，避免丢失更新和半成功。
- Vue 工作台含登录、队列、搜索过滤、建单、详情轨迹、分派、处理与客户确认。只展示后端允许操作，服务端是权限事实来源。
- MySQL/Redis 独立 Compose 项目、卷与端口；真实 MySQL/Redis 集成测试、前端构建及浏览器闭环验证。

## 后续边界

M2：FastAPI + LangGraph，真实 embedding → Qdrant；返回 chunk 引用和可信度；Java 先校验用户授权，再执行工具提案。不向 Python 提供业务库凭据。无 Key 时明确 disabled，无政策猜测。
M3：自动分派、接管、SLA 升级、通知 outbox、审计查询、经审核知识沉淀。
M4：完整 Compose、CI、Demo 与模型评测。M1 的启动工程及 CI 是基础设施提前交付，不代表 M4 已完成。

不做：支付/退款执行、真实短信邮件、生产部署、多租户、附件上传、实时 WebSocket。避免宣称通用企业级安全或生产就绪。
