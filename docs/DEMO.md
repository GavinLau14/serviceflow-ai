# Demo 与面试讲解路线

## 5–8分钟业务演示

1. 打开全栈入口18080；说明客户/客服/主管/管理员数据范围，密码在本地.env。
2. 客户alice输入“空调不制冷需要维修”：展示真实本地Embedding/Qdrant引用、retrieval_only标识，不把摘录说成LLM推理。
3. 明确选择家电并确认转人工；展示自动分派otheragent、公开沟通和处理轨迹。客户未确认之前客服不能关闭。
4. 客服提交解决说明，客户可退回或确认关闭。
5. 对已关闭工单，负责客服手动整理不含客户隐私的知识草稿；主管审核通过。说明不会未经发布直接进入AI向量库。
6. 展示主管SLA/审计与通知中心，说明同事务outbox、去重投递、版本控制、行锁以及范围过滤。
7. 停止AI容器，证明业务工单可继续使用且AI返回明确错误；恢复服务后索引及数据仍存在。

## v0.7–v0.9 进阶演示（约10分钟）

### 知识从内部审核进入客户检索

1. 管理员进入“服务知识库”→“已通过”，检索USB-C。展开“AI知识发布”，对比内部审核正文与独立公开摘要；公开版本只包含脱敏通用事实。
2. 当前本地演示知识8的有效公开版本为v3，标题“【演示】USB-C扩展坞供电状态记录”。它与已审核USB-C来源主题一致；早期光栅摘要用于向量边界测试，已被不可变新版本替代并撤回。
3. 客户咨询“USB-C扩展坞连接时供电状态不稳定，如何记录直连与扩展坞的状态差异？”，查看retrieval_only、引用与“查看公开来源版本”。这是实际向量命中的原文摘录，未调用远端语言模型。
4. 管理员展开“索引运行状态”，点击“核验此版本”；检查后显示最近核验一致。“修复此版本”需确认，沿用相同授权UUID/版本，不新增公开授权。真实丢失→修复过程见隔离测试及 [验证报告](INDEX_OPERATIONS_RESULTS.md)。
5. 可另用演示条目展示撤回：客户来源停止提供，旧历史建议被遮蔽；再次另填摘要并授权发布会创建新版本。已经创建的工单仍保留。演示后保留一条明确标记的有效虚构摘要，供后续检索。

本地样例的版本号会随演示操作变化，以界面最新记录为准；当前v3对齐证据见 [真实记录](verification/demo-knowledge-alignment.json)。公开脱敏应保持来源业务事实，系统不自动校验人工改写的语义一致性。

### 从风险队列继续处理

1. 主管或客服从“服务时限”进入队列；手机使用左侧常驻时钟图标。客服只看受派工单，主管看本组，管理员看全局，客户没有该内部入口。
2. 切换“已超时”“30分钟内到期”“等待客户”及“全部处理中”，按编号或标题检索，点击一条进入原工单。汇总受权限限制，不受关键词筛选影响；asOf是本次读取时刻。
3. 客服处理虚构工单并提交解决说明，进入等待客户。客户拒绝后，已记录等待时长结算到解决截止；客户确认后关闭，从未关闭风险队列移除。
4. 在工单“服务时限与审计”展开记录，查看累计等待和已结算截止。界面按分钟显示；秒级补偿查看 [实际SLA结果](verification/sla-live.json)。需要在界面直观看到分钟变化时，可在等待期间讲解知识流程后再恢复处理。
5. 首次响应时钟不暂停；未首次响应的历史演示记录仍可能显示首次响应超时。已有超时升级不会被暂停操作撤销。

## v0.10 管理员AI运行观测

1. 管理员从桌面导航或手机常驻图标进入“AI运行”，查看当前健康接口报告的模式、检索状态与语言模型配置。当前无模型Key时为仅检索原文；“接口可达”只表示健康探测成功。
2. 选择近1小时、近24小时或近7天，筛选当时模式或已关联工单，翻页查看运行UUID、记录耗时与原始引用/提案标记。汇总基于整个窗口，不随列表筛选改变。
3. 打开已关联工单，仍使用原有详情和处理权限。客服、主管和客户没有全局入口，对全局接口均403；页面不展示客户身份、咨询、回答或引用正文。
4. 历史引用条数和提案标记不是当前授权；核验也不调用语言模型。记录平均耗时不是生产性能基准，真实LLM验收仍按既有六场景脚本执行。

## 可复现证据

M1–M4_RESULTS.md分别记录里程碑当时的命令、结果及局限，verification目录保存摘要。JUnit是真实MySQL/Redis，Python另分fake契约与真实Embedding测试，浏览器替身场景有明确标签。完整stack smoke从浏览器同源API入口执行，不能替代真实远端LLM质量评测。最新模块结果见 [索引恢复](INDEX_OPERATIONS_RESULTS.md) 、[SLA风险处置](SLA_WORKBENCH_RESULTS.md) 与 [AI运行观测](AI_OPERATIONS_RESULTS.md)。源码学习与表述边界见 [面试讲解](INTERVIEW_GUIDE.md)。

## 面试可讨论的决策

- 为什么Java是唯一业务写入方，Python只做推理与受限工具提案。
- 为什么用服务端持久化提案、显式确认、owner行锁和同事务ticketId实现幂等，而不是相信模型的“创建成功”。
- 为什么团队锁要在INSERT之前获取；为何使用当前锁定读取而非旧事务快照统计负载。
- MyBatis局部缓存与SELECT FOR UPDATE的区别；UTC与JDBC Timestamp隐式时区转换的真实失败案例。
- SLA客户等待累计补偿、UTC自然时间策略的局限，outbox提交与投递的边界，以及为何不声称exactly-once外部消息。
- 知识审核、引用子集、原文回答约束的取舍；三条演示语料不代表生产召回率。

## 坦诚边界

远端LLM尚无Key实测；无真实邮件/短信、SSO、实时WebSocket聊天、生产负载/容灾/安全认证。没有捏造覆盖率、召回率或远程CI通过记录。实际完成的是可运行的Java业务系统、真实本地语义检索及可测试的安全Agent执行边界。
