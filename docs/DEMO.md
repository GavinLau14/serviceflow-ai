# Demo 与面试讲解路线

## 5–8分钟业务演示

1. 打开全栈入口18080；说明客户/客服/主管/管理员数据范围，密码在本地.env。
2. 客户alice输入“空调不制冷需要维修”：展示真实本地Embedding/Qdrant引用、retrieval_only标识，不把摘录说成LLM推理。
3. 明确选择家电并确认转人工；展示自动分派otheragent、公开沟通和处理轨迹。客户未确认之前客服不能关闭。
4. 客服提交解决说明，客户可退回或确认关闭。
5. 对已关闭工单，负责客服手动整理不含客户隐私的知识草稿；主管审核通过。说明不会未经发布直接进入AI向量库。
6. 展示主管SLA/审计与通知中心，说明同事务outbox、去重投递、版本控制、行锁以及范围过滤。
7. 停止AI容器，证明业务工单可继续使用且AI返回明确错误；恢复服务后索引及数据仍存在。

## 可复现证据

M1–M4_RESULTS.md分别记录里程碑当时的命令、结果及局限，verification目录保存摘要。JUnit是真实MySQL/Redis，Python另分fake契约与真实Embedding测试，浏览器替身场景有明确标签。完整stack smoke从浏览器同源API入口执行，不能替代真实远端LLM质量评测。

## 面试可讨论的决策

- 为什么Java是唯一业务写入方，Python只做推理与受限工具提案。
- 为什么用服务端持久化提案、显式确认、owner行锁和同事务ticketId实现幂等，而不是相信模型的“创建成功”。
- 为什么团队锁要在INSERT之前获取；为何使用当前锁定读取而非旧事务快照统计负载。
- MyBatis局部缓存与SELECT FOR UPDATE的区别；UTC与JDBC Timestamp隐式时区转换的真实失败案例。
- SLA绝对期限与等待客户扫描暂停的局限，outbox提交与投递的边界，以及为何不声称exactly-once外部消息。
- 知识审核、引用子集、原文回答约束的取舍；三条演示语料不代表生产召回率。

## 坦诚边界

远端LLM尚无Key实测；无真实邮件/短信、SSO、实时WebSocket聊天、生产负载/容灾/安全认证。没有捏造覆盖率、召回率或远程CI通过记录。实际完成的是可运行的Java业务系统、真实本地语义检索及可测试的安全Agent执行边界。
